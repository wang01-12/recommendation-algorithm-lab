## 一、实验目的

1. 掌握基于用户的协同过滤：找与当前用户最相似的 K 个用户，用公式 (7.5) 预测评分。
2. 掌握基于物品的协同过滤：找与目标电影最相似的 K 部电影，用减去均值的公式 (7.7′) 预测评分。
3. 理解近邻个数 K 对预测误差的影响，会用测试集误差 RMSE 选出 K。
4. 在网页上给电影打分，用自己写的两种算法为自己推荐电影，并对比两种算法的推荐结果。

## 三、实验题目

### 1. 背景

打开视频网站，首页总有"猜你喜欢"。网站并不认识你，它只知道两件事：**你给哪些电影打过分**，以及**其他观众给哪些电影打过分**。协同过滤（Collaborative Filtering）：只利用大家的评分，"集体协作"地帮每个人筛选电影。协同过滤有两种思路：

- **基于用户**：口味相似的人，喜欢的电影也相似。找到和你口味最像的人，看他们给这部电影打了几分；
- **基于物品**：同一个人对相似的电影，评分也相似。找到和这部电影最像的、你看过的电影，看你自己给它们打了几分。



#### （1）基于用户的协同过滤：五个步骤

**基本思想：** 根据评分找到与当前用户 U 口味相似的**邻居用户**，把邻居喜欢、而 U 还没看过的电影推荐给 U。

| 步骤 | 做什么 |
|---|---|
| ① 建立评分矩阵 | 把所有评分整理成"用户 × 电影"的评分矩阵，每个用户的评分是矩阵的**一行** |
| ② 计算用户相似度 | 计算用户 U 与其他每个用户的相似度：先求欧式距离 d，再转换为相似度 1/(1+d)，距离越小越相似 |
| ③ 找 K 个近邻用户 | 要预测 U 对电影 i 的评分时，在**评过电影 i 的用户**中，取与 U 最相似的 K 个人 |
| ④ 预测评分 | 用这 K 个近邻对电影 i 的评分，按相似度加权平均，得到 U 对 i 的预测评分（公式 7.5） |
| ⑤ 排序推荐 | 对 U 所有没看过的电影都预测评分，按预测评分从高到低排序，推荐前 N 部 |



#### （2）基于物品的协同过滤：五个步骤

**基本思想：** 用户越来越多时，用户之间的相似度要反复重新计算；而电影之间的相似性相对固定。所以改为计算**电影之间**的相似度：用户喜欢电影 A，而电影 B 和 A 很像，那他很可能也喜欢 B。

| 步骤 | 做什么 |
|---|---|
| ① 建立评分矩阵 | 与基于用户**完全相同**，每部电影的评分是矩阵的**一列** |
| ② 计算电影相似度 | 计算电影 i 与其他每部电影的相似度，公式与用户相似度相同，只是向量从"一行"换成"一列" |
| ③ 找 K 部近邻电影 | 要预测 U 对电影 i 的评分时，在 **U 自己评过的电影**中，取与 i 最相似的 K 部 |
| ④ 预测评分 | 看 **U 自己**给这 K 部电影打的分比它们的均值高多少（偏差），按相似度加权平均，再加到电影 i 的均值上，得到 U 对 i 的预测评分（公式 7.7′） |
| ⑤ 排序推荐 | 对 U 所有没看过的电影都预测评分，按预测评分从高到低排序，推荐前 N 部 |





### 2. 整体流程（main.py）

```
第1步  读取数据              943 位用户、80 部电影、21027 条评分
第2步  划分训练集 / 测试集    8 : 2，测试集的评分先藏起来
第3步  构建评分矩阵           943 × 80，没评分记 0
        │
第4步  choose_best_k()        计算相似度矩阵 → 对每个候选 K 预测测试集 → RMSE 最小的 K
        │                     分别用于 基于用户（user_cf.py）和 基于物品（item_cf.py）
        │
第5步  打开网页               你打分 → 两种算法分别为你推荐 10 部电影，可随时切换对比
```

## 四、实验数据

本实验使用 MovieLens 公开数据集（明尼苏达大学 GroupLens 实验室发布）中 943 位真实观众的评分，选取 80 部经典电影，片名改为大家熟悉的中文名，评分保持原样（1～5 分）。你要亲手实现这两种算法，用测试集选出最合适的近邻个数 K，最后在网页上给自己打分，看看两种算法分别为你推荐什么。

**movies.csv**（80 部电影）

| 字段 | 含义 | 示例 |
|---|---|---|
| movie_id | 电影编号 1～80 | 4 |
| name | 中文片名 | 玩具总动员 |
| en / year / genres | 英文名 / 年份 / 类型 | Toy Story / 1995 / 动画\|儿童\|喜剧 |

**ratings.csv**（21027 条评分）

| 字段 | 含义 | 示例 |
|---|---|---|
| user_id | 用户编号 1～943 | 1 |
| movie_id | 电影编号 1～80 | 4 |
| rating | 评分 1～5 | 5 |

在程序里，评分被整理成评分矩阵 `rating_matrix`（943 行 × 80 列）：`rating_matrix[user_index, movie_index]` 是该用户对该电影的评分，0 表示没评过。注意文件里的编号从 1 开始，矩阵下标从 0 开始。

```
            电影0  电影1  电影2  …  电影79
  用户0   [   5      3      0    …     4   ]   ← rating_matrix[0]     一个用户的评分向量（一行）
  用户1   [   4      0      0    …     0   ]
   …
  用户942 [   0      5      0    …     0   ]
              ↑
           rating_matrix[:, 0]  一部电影的评分向量（一列）
```

## 五、需要实现的内容

共 5 个函数。下面给出每个函数的**功能、输入、输出**。



### 5.1 基于用户的协同过滤

---



#### 函数 1　`user_cf.compute_similarity(rating_matrix)`

| 项目 | 说明 |
|---|---|
| 功能 | 计算所有用户两两之间的相似度。两个用户的相似度：先求两人的欧式距离 d（**只比较两人都评过分的电影**），再转换为相似度 1 / (1 + d)。两人没有共同评过分的电影时，相似度为 0；用户与自己的相似度（对角线）也为 0。 |
| 输入 | `rating_matrix`：评分矩阵，numpy 数组，形状 (用户数, 电影数)，0 表示没评过 |
| 输出 | `similarity_matrix`：用户相似度矩阵，numpy 数组，形状 (用户数, 用户数)，对称矩阵 |
| 公式 | 式 (7.1)(7.2)，见下方 |

$$
d(a,b)=\sqrt{\sum_{j}\left(r_{a,j}-r_{b,j}\right)^2}\qquad sim(a,b)=\frac{1}{1+d(a,b)}
$$

其中 j 只取用户 a、b 都评过分的电影。



#### 函数 2　`user_cf.predict_rating`

| 项目 | 说明 |
|---|---|
| 功能 | 预测用户对一部电影的评分。近邻：**在评过这部电影的其他用户中**，与该用户相似度最高的 k_neighbors 个用户。按公式 (7.5) 加权平均；相似度之和为 0 时，预测分为 3。 |
| 输入 | `rating_matrix`：评分矩阵，形状 (用户数, 电影数)<br>`similarity_matrix`：函数 1 返回的用户相似度矩阵<br>`user_index`：用户的行下标（从 0 开始）<br>`movie_index`：电影的列下标（从 0 开始）<br>`k_neighbors`：近邻个数 K |
| 输出 | `predicted_rating`：预测评分（float） |
| 公式 | 式 (7.5)，见下方 |

$$
\hat r_{u,i}=\frac{\sum_{v} sim(u,v)\times r_{v,i}}{\sum_{v} sim(u,v)}
$$

其中 v 是 K 个近邻用户。大白话：**预测分 = Σ(近邻相似度 × 近邻对这部电影的评分) ÷ Σ近邻相似度**



---



### 5.2 基于物品的协同过滤

#### 函数 3　`item_cf.compute_similarity`

| 项目 | 说明 |
|---|---|
| 功能 | 计算所有电影两两之间的相似度。每部电影的评分向量是评分矩阵的**一列**。两部电影的相似度：先求欧式距离 d（**只比较两部电影都被评过分的用户**），再转换为相似度 1 / (1 + d)。没有共同评分的用户时，相似度为 0；对角线为 0。 |
| 输入 | `rating_matrix`：评分矩阵，形状 (用户数, 电影数)，0 表示没评过 |
| 输出 | `similarity_matrix`：电影相似度矩阵，numpy 数组，形状 (电影数, 电影数)，对称矩阵 |
| 公式 | 与函数 1 相同，只是向量从"一行"换成"一列"　　式 (7.1)(7.2) |



#### 函数 4　`item_cf.predict_rating`

| 项目 | 说明 |
|---|---|
| 功能 | 预测用户对一部电影的评分（减去电影评分均值的改进公式）。近邻：**在该用户评过分的其他电影中**，与这部电影相似度最高的 k_neighbors 部电影。电影的评分均值只统计评过分的用户（0 不算）。按公式 (7.7′) 计算；相似度之和为 0 时，预测分为这部电影的评分均值；结果超出 1～5 时截断到 1～5。 |
| 输入 | 与函数 2 相同，其中 `similarity_matrix` 是函数 3 返回的电影相似度矩阵 |
| 输出 | `predicted_rating`：预测评分（float） |
| 公式 | 式 (7.7′)，见下方 |

$$
\hat r_{u,i}=\bar r_i+\frac{\sum_{j} sim(i,j)\times\left(r_{u,j}-\bar r_j\right)}{\sum_{j} sim(i,j)}
$$

其中 j 是 K 部近邻电影；r 上加一横表示评分均值，即电影 i、电影 j 各自的平均评分。



### 5.3 预测评分，选择最优 K

#### 函数 5　`main.choose_best_k`

| 项目 | 说明                                                         |
| ---- | ------------------------------------------------------------ |
| 功能 | 为算法选出最优的近邻个数 K。思路是"藏起一部分已知评分当考题"，看哪个 K 预测这些考题最准。<br>**1. 数据的准备（main.py 已完成，本函数不用做）**：main.py 第 2 步把全部评分随机分成两份：80% 是"已知评分"（训练集），用来建评分矩阵 `rating_matrix`；20% 是"隐藏评分"（测试集 `test_set`），没有填进评分矩阵，在矩阵中对应的格子是 0，相当于算法不知道这些评分。<br>**2. 计算相似度**：调用 `algorithm.compute_similarity(rating_matrix)`，得到相似度矩阵。相似度只用已知评分计算，与 K 无关，只需计算一次。<br>**3. 对每个候选 K 预测考题**：对 `candidate_k_list` 中的每个 K，遍历测试集的每一条记录（用户、电影、真实评分），调用前面已完成的预测函数 `algorithm.predict_rating(rating_matrix, similarity_matrix, 用户下标, 电影下标, K)`，得到预测评分。不需要另写预测算法：algorithm 是 `user_cf` 时就是函数 2，是 `item_cf` 时就是函数 4。测试集中的 user_id、movie_id 从 1 开始编号，作为矩阵下标时要减 1。<br>**4. 计算误差**：把这个 K 下所有记录的预测评分与真实评分比较，计算均方根误差 RMSE（公式见下方），记入 `rmse_list`。<br>**5. 选出最优 K**：所有候选 K 都算完后，RMSE 最小的那个 K 就是最优 K。 |
| 输入 | `algorithm`：算法模块 `user_cf` 或 `item_cf`。本函数只调用它的两个函数 `algorithm.compute_similarity(...)` 和 `algorithm.predict_rating(...)`，所以同一个函数两种算法都能用<br>`rating_matrix`：用已知评分（训练集）建成的评分矩阵，形状 (943, 80)，隐藏评分对应的格子为 0<br>`test_set`：隐藏评分（测试集），DataFrame，三列 `user_id`、`movie_id`、`rating`，`rating` 就是考题的标准答案<br>`candidate_k_list`：候选 K 的列表，如 `[5, 10, 20, 30, 50, 80, 120, 200, 400]` |
| 输出 | `best_k`：最优 K（int）<br>`rmse_list`：列表，`rmse_list[j]` 是 `candidate_k_list[j]` 对应的 RMSE（float） |
| 公式 | 见下方                                                       |

$$
RMSE=\sqrt{\frac{1}{n}\sum_{t=1}^{n}\left(\text{真实评分}_t-\text{预测评分}_t\right)^2}
$$

其中 n 为测试记录条数。

`choose_best_k()` 只依赖 `compute_similarity()` 和 `predict_rating()` 这两个"接口"，所以同一个函数既能给基于用户用，也能给基于物品用。



**验收结果：** 运行 `python main.py`，基于用户部分应输出（数据划分固定，结果应一致）：

```
第4步  选择近邻个数 K（用时 X.X 秒，因电脑而异）：
         K = 5    测试集 RMSE = 1.0229
         K = 10   测试集 RMSE = 0.9755
         ……
         K = 80   测试集 RMSE = 0.9302
         ……
         K = 400  测试集 RMSE = 0.9489
       → 最优 K = 80，RMSE = 0.9302
```

运行完会自动打开网页，此时可以先看基于用户的推荐（基于物品的按钮暂时是灰的）。

### 5.4 在网页上对比两种算法

1. 运行 `python main.py`，浏览器自动打开推荐网页（没有自动打开时，复制终端里显示的地址，一般是 `http://127.0.0.1:8000`）。
2. **第一幕**：给看过的电影点星打分，至少 3 部，建议 10 部以上，喜欢的和不喜欢的都打。
3. 点「开映」。评分会保存到 `data/my_ratings.json`，你作为第 944 号用户加入数据，两种算法各自用最优 K 为你预测并推荐 10 部电影。
4. 用页面上方的 **基于用户 / 基于物品** 按钮切换，对比：
   - **第二幕 海报墙**：两种算法推荐的 10 部电影有什么不同？
   - **第三幕 幕后**：
     - 基于用户看"和你口味最像的观众"；基于物品看"和这部片最像的电影"；
     - "预测分是怎么算的"面板列出了公式的每一项，并核对你的 `predict_rating()`；
     - 最下方是 K 与测试集误差的曲线。
   - 点任意海报，打开"票根"查看这部电影的预测过程。
5. 修改几部电影的评分（例如把喜欢的科幻片都改成 1 星），重新推荐，观察两种算法的结果如何变化。

> 网页状态条上 4 个绿灯表示两个算法文件的函数都已完成。改了 `user_cf.py` / `item_cf.py` 后，在网页上重新推荐即可，不用重启；但 K 是在 main.py 启动时选的，若改动影响了 K，需要重新运行 main.py。

## 六、程序完整流程

```
python main.py
  第1步 读取数据
  第2步 划分训练集 / 测试集（8:2）
  第3步 构建评分矩阵
  第4步 choose_best_k(algorithm, ...)                                    ← 函数 5
          ├─ algorithm.compute_similarity(rating_matrix)                 ← 函数 1 / 函数 3
          └─ 对每个候选 K：algorithm.predict_rating(...) 预测测试集       ← 函数 2 / 函数 4
             → RMSE → 最优 K
        （algorithm 依次为 user_cf、item_cf）
  第5步 打开网页：打分 → my_ratings.json → 两种算法推荐 → 切换对比
```
